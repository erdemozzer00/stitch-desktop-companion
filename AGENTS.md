# Working instructions

Read `context/PROJECT.md`, `context/ROADMAP.md`, and `context/ACTIVE.md` before implementation. Keep one active phase.

- Speak Turkish with the user. Write code, comments, and project records in English.
- Improve decision quality rather than defaulting to agreement. Raise material assumptions, risks, and better alternatives directly; explain the reason, evidence, and proposed alternative. Do not manufacture objections.
- Separate known facts, assumptions, risks, and recommendations when useful. State high, medium, or low confidence when uncertainty affects a decision. Update conclusions when stronger evidence appears.
- Reuse the supplied model and rig. Choose the smallest maintainable solution; avoid speculative features, frameworks, and test scaffolding.
- Inspect current files and evidence before making claims. Verify uncertain Blender or Windows behavior against the installed tools and primary documentation.
- Preserve the original downloads. Work on copies under `.local/` and disable Blender file auto-execution when opening third-party files.
- Keep `.local/`, `model/`, and `media/` out of Git. Do not publish third-party models, textures, or renders while redistribution remains unverified; see `THIRD_PARTY.md`.
- Finish the active phase, record its outputs, checks, limitations, and next step, then stop at the phase handoff. The user requested phase-by-phase work; do not silently start later phases or introduce extra approval procedures.
- Mark a phase complete only when its exit criteria have evidence. Distinguish source inspection, rendered motion, local Windows behavior, packaged-app behavior, and target-computer acceptance.
- Never claim error-free operation or professional animation quality from code execution alone. Review motion visually and test desktop behavior on Windows.
- Update the short canonical records rather than creating a parallel context system. Run focused checks appropriate to the change.
